# LxChat「微信深度控制 + 系统级能力」落地规划

日期：2026-08-28
状态：待验收
范围：聚焦二块 —— 微信（最常用）深度封装、Android 系统级能力。交付方式：分批实现，每批提交并通过 GitHub CI 后再验收下一批。

---

## 0. 前提盘点（现状，避免重复建设）

已完成并已验证（GitHub CI 通过）的底座：

- Agent 自动化：`TaskExecutionEngine`、工具矩阵（Git/Shell/IM/设备/提醒/子代理/Skill 自学/工作流/定时）、Plan/Agent/Auto 风险分级 + 审批。
- **系统级工具**（`DeviceToolProvider`，`device_*`）：设备信息、电池、时间、屏幕、存储、内存、网络、WiFi 查询、传感器、剪贴板读写、音量、手电、通知、应用列表/详情、振动。
- **无障碍 UI 操作**（`AndroidAppControllerToolProvider`，`android_*`）：读无障碍节点树、开 App、点击、输入、返回、回桌面；内置微信/支付宝/抖音等 15 个别名 + 任意包名。
- **微信 iLink 通道**（`WeixinIlinkApi`）：账号二维码登录、`getupdates` 收消息、`sendmessage` 发文本、发图片直链（`/sendimage`）、发文件直链（`/sendfile`）、转发缓存媒体（`/forward`）、`sendtyping` 打字状态、`getconfig`、`notifystart/stop`。

因此本规划不做重复，只做**增量**：把「已能做的操作」封装成稳定、可被 AI 直接调用的高价值动作，并补齐缺口。

## 1. 微信深度控制

### 1.1 能力矩阵（现状 → 目标 → 路径）

| # | 能力 | 现状 | 实现路径 | 优先级 |
|---|------|------|----------|--------|
| W1 | 收发文本 | ✅ 已有 | iLink `sendmessage` | 基线 |
| W2 | 发图片/文件 | ✅ 已有 | iLink `/sendimage /sendfile` | 基线 |
| W3 | 转发媒体 | ✅ 已有 | iLink `/forward` | 基线 |
| W4 | 打字状态 | ✅ 已有 | iLink `sendtyping` | 基线 |
| W5 | 定时/条件提醒发微信 | ➖ 需编排 | iLink + 定时任务框架 | 高 |
| W6 | 撤回消息 | ❓ 待核对 | iLink 协议若支持则用；否则无障碍兜底 | 中 |
| W7 | 好友备注/群管理/置顶 | ❓ 待核对 | 同上 | 中 |
| W8 | 打开某好友聊天 / 搜联系人 | ➖ 部分 | 无障碍 UI（`android_open_app`+`android_*`） | 高 |
| W9 | 朋友圈（查看/发布/点赞） | ❌ 受限 | 无障碍 UI 兜底，稳定性差 | 低 |
| W10 | 收款码 / 支付 | ❌ 受限 | 无障碍 UI 兜底，**安全敏感须审批** | 中 |

> 说明：W6/W7/W9/W10 是否可用取决于 iLink 服务端协议支持面，**不能凭推断写死**。W6/W7 首期做「协议探测 + 无障碍兜底」两路并行；W9/W10 因稳定性与安全风险放后，且默认仅 Plan/Agent 模式、需用户确认。

### 1.2 首期交付（微信部分）

1. **微信深度技能包**（一个 `WeChatSkill`，基于现有 `Skill`/`SubAgent` 机制）：
   - 组合指令：「帮我在微信给 {联系人} 发消息 {内容}」「发文件 {文件} 给 {联系人}」→ 自动编排 iLink 或无障碍。
   - 角色感知：联系人→会话 id 的映射缓存（现有 `ImGatewayStore` 持续内存化，重启恢复）。
   - 失败回退：iLink 通道断 → 打印清晰提示，而非神秘报错。
2. **开发者动作**：在 `AndroidAppControllerToolProvider.KNOWN_APPS` 已含微信基础上，补充「打开与 {联系人} 的聊天」这类微信专用 UI 动作的封装（新增 1-2 个 `wechat_*` 便捷工具），让 AI 少一次「dump→点搜索→点人」的碎操作。
3. **协议探测**：接一个「微信能力自检」工具，登录后探测并缓存在线能力表（`send/file/typing/revoke/group/…`），AI 据此决策用 iLink 还是无障碍，避免盲试。

## 2. Android 系统级能力

### 2.1 覆盖图（现有 `device_*` → 目标）

已覆盖（不需做）：信息/电池/时间/屏幕/存储/内存/网络/WiFi 查询/传感器/剪贴板/音量/手电/通知/应用列表。

**首期新增（按价值排序）：**

| # | 能力 | 说明 | 权限 | 优先级 |
|---|------|------|------|--------|
| S1 | 拨打电话 | `ACTION_DIAL`/`ACTION_CALL` | `CALL_PHONE` | 高 |
| S2 | 发送短信 | `SmsManager`，可带收件人+内容 | `SEND_SMS` | 高 |
| S3 | 快读相册/单条图片 | `MediaStore` 读取最近媒体 | 存储/媒体读权限 | 高 |
| S4 | 保存图片/文件到相册/下载 | `MediaStore` insert | 媒体写权限 | 高 |
| S5 | 文件管理（浏览/复制/移动/删除） | SAF `ACTION_OPEN_DOCUMENT` + DocumentsProvider | 用户授权 | 高 |
| S6 | 开关蓝牙/WiFi/飞行/热点 | 系统 API（部分需系统权限，非 root 有限） | 依赖版本 | 中 |
| S7 | 截图（前台） | 无障碍 `takeScreenshot` | 无障碍权限 | 中 |
| S8 | 屏幕亮度 | 设置亮度 + 失效恢复 | WRITE_SETTINGS | 低 |
| S9 | 媒体播放控制（播放/暂停/音量） | MediaSession/系统广播 | 无 | 低 |
| S10 | 录音 | MediaRecorder | `RECORD_AUDIO` | 低 |

> 权限策略：所有敏感权限（通话/短信/定位/相机/录音）按**运行时授权 + 首次调用引导授权页**；工具风险级归 `Moderate`，Auto 模式下仍默认需审批，避免误拨号/误发短信。

### 2.2 交付方式
- 新增一个 `SystemToolsToolProvider`（`system_*`），或在 `DeviceToolProvider` 内扩展 `device_phone_call` 等，**统一放 DeviceToolProvider 扩展**，避免再注册新 Provider。
- 权限集中在 `AndroidManifest` 声明 + 一个统一的「权限检查 → 请求 → 结果」Helper 复用跨工具。

## 3. 分批交付计划（每批提交并过 CI 后验收）

| 批次 | 内容 | 验收标准 |
|------|------|----------|
| P1 | 微信深度技能包 + 微信能力自检工具 + 1-2 个 `wechat_*` 便捷动作 | 仓库源码过 GitHub CI；本地可用 skill 指令发微信 |
| P2 | 系统级 S1-S5（通话/短信/相册读/相册写/SAF 文件）+ 权限 Helper | 过 CI；本地语音/文字能拨号、发短信、读存媒体 |

> 顺序依据：P1 使用频次最高、纯依赖已有基建、风险最低先做；P2 高频且权限明确；P3 权限较多放中；P4 编排深化最后。每批独立可验收，任一批失败不影响其它。

## 4. 风险与护栏

- **权限安全**：通话/短信/媒体/录音均运行时授权，失败时给出可直接跳转的引导；自动模式下高敏操作仍需审批。
- **微信协议不确定性**：W6/W7/W9/W10 以「协议探测结果」为准，先测后封装，不乐观写死。
- **稳定性**：无障碍路径慢且依赖各 App 界面暴露，微信发送优先走 iLink（稳定），无障碍仅兜底。
- **隐私**：短信/通话/相册涉及隐私，工具级日志打码，不落库敏感正文。
